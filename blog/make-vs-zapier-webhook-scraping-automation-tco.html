1. How Billing Units Actually Work: Make Operations vs Zapier Tasks

Both platforms meter execution volume differently, and choosing the wrong unit model can multiply your monthly automation bill by 3× to 8×:

  • Make.com (Operations): Every module execution (including the initial trigger check and JSON parser) counts as 1 operation. Formula: Monthly Operations = (M_runs × N_modules_per_run) + P_empty_polls. Using instant webhooks instead of scheduled polling sets P_empty_polls = 0.
  • Zapier (Tasks): The initial trigger does not count as a task, while each downstream action step that executes counts as 1 task. Formula: Monthly Tasks = M_runs × (N_modules_per_run - 1).

2. Concrete Example: 5-Step Scraping-to-Database Pipeline Running 50 Times/Day

Suppose an engineering team triggers an instant webhook 50 times per day (M = 1,500 runs/month) to: (1) receive webhook URL, (2) call ScraperAPI HTTP endpoint, (3) parse JSON fields, (4) filter changed prices, and (5) upsert rows into PostgreSQL/Google Sheets (N = 5 modules):

  • Make.com Usage: 1,500 runs × 5 modules = 7,500 operations/month. Fits comfortably inside Make Core (10,000 operations/month).
  • Zapier Usage: 1,500 runs × 4 action steps = 6,000 tasks/month. Requires a 5,000-to-10,000 task tier on Zapier Professional.
